# 낙지도 정보구조 (IA)

DEM 경사 분석과 머신러닝 예측으로 개인 낙상위험과 지역 보행환경 위험을 산출해
고령자와 기초자치단체에 제공하는 웹 서비스.

- 문서 버전: 2026-08-12
- 대상 저장소: `onebeaness/antifall_map`
- 짝 문서: `docs/FUNCTIONAL_SPEC.md` (기능명세서)

---

## 1. 이용자 구분

| 구분 | 이용자 | 진입 경로 | 목적 |
|---|---|---|---|
| B2C | 65세 이상 본인, 보호자, 생활지원사 | `/` 개인용 진입 | 본인 낙상위험 확인, 보행 경로 확인 |
| B2G | 기초자치단체 안전·고령정책 담당 | `/` 기관용 진입 | 관할 구역 보행환경 위험 파악, 정비 우선순위 판단 |

직접 입력이 어려운 고령자 특성을 전제로, 보호자 대리 입력과 방문 현장 입력을
모두 허용하는 구성. 별도 계정 분기 없이 진입 버튼으로만 구분.

---

## 2. 화면 계층

```
/                       랜딩 (개인용 · 기관용 분기)
├── /register           간편 등록 (이름·생년월일·성별·낙상경험)
│   └── /me             진단 허브
│       ├── /me/simple      간편 확인 (6문항)
│       ├── /me/precision   심층 확인 (42문항)
│       ├── /me/report      개인 리포트
│       └── /me/route       경로 경사도 확인
└── /dashboard          기관 대시보드
/offline                오프라인 안내 (서비스워커 폴백)
```

깊이 3단계. 최하위 화면에서 상위로 돌아가는 경로를 모든 화면에 배치.

## 3. 화면 정의

### 3.1 `/` 랜딩

- 역할: 이용자 구분과 서비스 목적 안내
- 구성: 개인용 블록, 기관용 블록의 2분할
- 이동: 개인용 → `/register` 또는 `/me`, 기관용 → `/dashboard`

### 3.2 `/register` 간편 등록

- 역할: 예측 모델의 기본 입력값 수집
- 수집 항목: 이름, 생년월일 8자리, 성별, 최근 1년 낙상 경험
- 생년월일에서 만 나이를 자동 계산하므로 나이 문항 별도 미수집
- 낙상 경험은 재발위험 모델(Model B)의 실행 여부를 가르는 값
- 이동: 저장 후 `/me`

### 3.3 `/me` 진단 허브

- 역할: 두 가지 확인 방식의 선택과 이후 행동 안내
- 구성: 간편 확인 카드, 심층 확인 카드, 경로 확인 카드
- 완료 상태를 카드에 표시. 심층 확인은 간편 확인을 포함하므로 심층 완료 시 두 카드 모두 완료 처리
- 이동: `/me/simple`, `/me/precision`, `/me/report`, `/me/route`

### 3.4 `/me/simple` 간편 확인

- 역할: 6문항으로 낙상위험 등급을 즉시 제시
- 문항: 성별, 연령, 이동보조기, 처방약 종류수, 1년내 입원, 주관적 건강상태
- 결과: 낙상 위험 점수, 낙상 경험자에 한해 재발 위험 점수, 주요 위험요인 상위 항목
- 이동: `/me/precision` (심층 확인 유도), `/me`

### 3.5 `/me/precision` 심층 확인

- 역할: 42문항으로 정밀 위험도와 영역별 프로파일 산출
- 진행 구조: 4개 묶음(기본 정보 10, 신체 기능 14, 질환·마음 6, 영양 상태 12)
- 좌측 단계 안내는 5단계 표기(4개 묶음 + AI 분석 결과)
- 간편 확인을 마친 이용자는 앞 6문항을 건너뛰고 남은 36문항만 응답
- 응답은 문항 단위로 자동 저장. 중단 후 재진입 시 이어서 진행
- 완료 시 간편 확인 결과도 함께 갱신. 심층만 마쳐도 허브의 간편 카드가 활성 상태
- 이동: 완료 후 `/me/report`

### 3.6 `/me/report` 개인 리포트

- 역할: 영역별 위험 수준과 생활 개선 안내 제시
- 구성: 6개 영역 레이다 차트, 영역별 막대와 안내 문구
- 6개 영역: 신체 기능, 질환 부담, 약물 복용, 영양 상태, 정서·마음, 일상생활 수행
- 인쇄 및 PDF 저장 지원
- 이동: `/me`, `/me/route`

### 3.7 `/me/route` 경로 경사도 확인

- 화면 제목: 경로 경사도 히트맵
- 역할: 출발지와 목적지 사이 보행 경로의 구간별 경사 제시
- 구성: 출발지·도착지 검색 입력, 이동 날짜 입력, 요약 지표 4장, 경로 지도, 고도 프로파일, 구간별 경사 막대, 구간 데이터 표(접힘)
- 기상특보 발효 시 지도 위에 배너 노출
- 지도의 구간·급경사 라벨·임의 지점 클릭으로 카카오 로드뷰 연결
- 보행자 경로만 취급. 자동차 경로 미제공
- 프로필 확인 절차 없음. 등록하지 않아도 직접 접근 가능
- 이동: `/me`

### 3.8 `/dashboard` 기관 대시보드

페이지 구성 순서:

| 순서 | 블록 | 내용 |
|---|---|---|
| 1 | 요약 지표 | 분석 대상 수, 위험·주의·양호 등급별 개수 |
| 2 | 위험도 지도 | 자치구 25개 → 행정동 드릴다운 단계형 choropleth |
| 3 | 위험 상위 표 | 지도의 드릴다운 단계를 따라가는 순위표 |
| 4 | 선택 행정동 상세 | 경사 프로필, 보도 폭·재질, 인구 지표, 시간대별 생활인구 |
| 5 | 투입 효과 기대 지역 | 효과지수 상위 12개 행정동 |
| 6 | 처음 화면 이동 버튼 | |
| 7 | 주의 문구 | 참고용 스크리닝 고지 |
| 8 | 산출 방식과 자료 | 산식, 효과지수, 등급, 자료 출처, 질문 8건 |

본문 블록에는 수치만 배치. 계산 근거와 자료 설명은 8번 블록으로 집약.
8번 블록의 질문 8건은 접힘 상태가 기본.

### 3.9 `/offline` 오프라인 안내

- 화면 제목: 네트워크 연결이 필요합니다
- 역할: 서비스워커가 화면 요청 실패 시 대체 표시
- 문항 데이터는 번들에 포함되어 오프라인에서도 열람 가능. 예측 결과 산출과 지도·날씨 조회만 연결 필요
- 이동 버튼 없음. 연결 복구 후 이전 화면으로 되돌아가는 방식

## 4. 이동 규칙

| 규칙 | 대상 화면 |
|---|---|
| 프로필 없으면 `/register`로 이동 | `/me`, `/me/simple`, `/me/precision`, `/me/report` |
| 심층 확인 기록 없으면 안내 카드 표시 | `/me/report` |
| 확인 절차 없이 접근 가능 | `/`, `/register`, `/me/route`, `/dashboard`, `/offline` |

- 랜딩의 개인용 버튼은 프로필 유무에 따라 `/me` 또는 `/register`로 분기
- 심층 확인 진입 시 간편 확인 완료 여부로 시작 문항 위치를 결정
- 모든 하위 화면에 상위 화면 복귀 버튼 배치. `/offline`은 예외

## 5. 데이터 보관

현재 저장소는 브라우저 `localStorage`. 서버 계정 체계 미도입 상태.

| 키 | 용도 | 값 |
|---|---|---|
| `ansim.profile` | 등록 프로필 | 이름, 생년월일, 성별, 낙상경험 |
| `ansim.assessment.simple` | 간편 확인 기록 | 응답 원본, 예측 결과, 저장 시각 |
| `ansim.assessment.precision` | 심층 확인 기록 | 응답 원본, 예측 결과, 저장 시각 |
| `ansim.draft.simple` | 간편 진행 초안 | 응답, 현재 문항 번호 |
| `ansim.draft.precision` | 심층 진행 초안 | 응답, 시작 문항 위치 |

기록 삭제 시 초안 2건도 함께 삭제. 초안이 남으면 기록을 지운 뒤에도
이어하기 안내가 뜨는 문제가 생김.

`supabase/schema.sql`에 서버 저장 전환용 스키마를 준비. 전환 시
`frontend/src/lib/storage.ts`의 저장소 구현만 교체하는 구조.

## 6. API 계약

기본 경로 `NEXT_PUBLIC_API_BASE`. 프론트엔드는 이 서버의 `/api/*` 만 호출.

| 메서드 | 경로 | 용도 | 필요 키 |
|---|---|---|---|
| GET | `/api/health` | 모델 적재 여부, 키 설정 상태, 보행로 색인 크기 | 없음 |
| GET | `/api/config/map` | 브라우저 지도 SDK 키 전달 | 없음 |
| POST | `/api/assess/simple` | 간편 확인 예측 | 없음 |
| POST | `/api/assess/precision` | 심층 확인 예측 | 없음 |
| GET | `/api/poi` | 장소명·주소 검색 | `TMAP_APP_KEY` |
| POST | `/api/route` | 보행자 경로와 구간별 경사 | `TMAP_APP_KEY` |
| GET | `/api/weather` | 일별 날씨와 보행 주의 등급 | 선택 |
| GET | `/api/weather/warnings` | 발효 중 기상특보 | `KWEATHER_API_KEY` |
| GET | `/api/population/dong` | 총인구·인구밀도·평균나이·노령화지수 | `SGIS_CONSUMER_KEY/SECRET` |
| GET | `/api/population/floating` | 행정동 시간대별 생활인구 | `SEOUL_OPENAPI_KEY` |
| GET | `/api/population/floating/citywide` | 서울 전역 일평균·피크 생활인구 | `SEOUL_OPENAPI_KEY` |
| GET | `/api/safety/lights` | 반경 내 보안등 수 | `DATA_GO_KR_KEY` |

행정동 보행 경사위험도는 API가 아니라 정적 자산으로 배포:
`frontend/public/geo/seoul_dong_risk.geojson`, `seoul_gu_risk.geojson`.

### 상태 코드

| 코드 | 의미 |
|---|---|
| 422 | 입력 형식 오류 |
| 502 | 외부 API 응답 실패 |
| 503 | 필요한 키 미설정, 모델 미적재 |

통신 자체가 실패하면 프론트엔드가 상태 0으로 처리하고
"서버에 연결할 수 없습니다" 문구를 표시.

## 6-1. 배포 구조

| 구성 | 배포 대상 | 산출물 |
|---|---|---|
| 프론트엔드 | Cloudflare Pages 등 정적 호스팅 | Next.js 정적 내보내기 `frontend/out` |
| 백엔드 | Render 등 Python 런타임 | FastAPI + 예측 모델 4종 |

- 프론트엔드 빌드 변수: `NEXT_PUBLIC_API_BASE`, `NEXT_PUBLIC_TMAP_APP_KEY`
- 지도 SDK 키는 백엔드 키와 분리. 브라우저 번들에 노출되므로 별도 앱으로 발급
- 빌드 시점 변수를 바꾸지 않고도 지도 키를 교체할 수 있도록 `/api/config/map` 경유 조회 경로를 병행

### PWA

| 항목 | 값 |
|---|---|
| 표시 이름 | 낙지도 |
| 표시 방식 | standalone, 세로 고정 |
| 테마색·배경색 | `#1E2761`, `#F2F5FB` |
| 아이콘 | 192, 512, maskable 512, apple-touch-icon |
| 캐시 대상 | 앱 셸, 정적 자산, 아이콘 |
| 캐시 제외 | API 응답 |

화면 요청은 네트워크 우선, 실패 시 캐시, 캐시에도 없으면 `/offline`.
정적 자산은 캐시 우선.
